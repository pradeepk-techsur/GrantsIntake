<objective>
Close UAT gap uat/5 (PRD-INTAKE-019C). Today the "Import to Workspace" flow
succeeds server-side (the import endpoint returns 201, is idempotent, and has
been verified live across 25 opportunities) but the user perceives "nothing
happened": the confirm handler redirects to `/applicant/applications`
(WorkspaceListPage), which (a) never reads the `importedFromGrantsGov` router
state, so shows no success message, and (b) lists only *workspaces* via
`['my-workspaces']` — the import creates an internal `opportunities` row
(`status='imported'`, `source='grants_gov_import'`), NOT a workspace, so the
imported item is invisible there.

This plan fixes the **redirect destination and its feedback only**. It does NOT
touch the import endpoint, the import service's write path, migration 018, or
ingestion — all of which work and are proven idempotent.

Design decision (justified): The imported opportunity is an internal
`opportunities` row with `status='imported'` and no `public_slug`. The public
detail route `GET /api/v1/opportunities/:id` (publicOpportunities.ts, lines
116–126) returns **404 for any non-`published` opportunity** to a
non-grantor caller. So redirecting the applicant to `/opportunities/:id` (the
page that already renders the imported badge) would 404. Loosening that access
control is out of scope and security-sensitive. Therefore the fix keeps the
redirect on `/applicant/applications` and surfaces the imported opportunity
there via a **minimal authenticated read endpoint** plus a success banner —
staying inside this phase's frontend/read scope.

Purpose: Make the successful import observable to the user — the exact truth
UAT test 5 checks.
Output: A new `GET /external-opportunities/imported` read endpoint, a client
method + type, a success banner + imported-opportunities list on
WorkspaceListPage (reusing the existing "Imported from Grants.gov" badge), and
integration + e2e tests re-proving the end-to-end truth.
</objective>

          go.org_name              AS funder_name,
          o.program_area,
          o.funding_amount_max     AS max_award_amount,
          o.application_close_date,
          o.source,
          o.created_at             AS import_timestamp
     FROM opportunities o
     LEFT JOIN programs p ON o.program_id = p.program_id
     LEFT JOIN grantor_organizations go ON p.grantor_org_id = go.org_id
