<objective>
Close the three Phase 8 gaps found in UAT/gate verification:

1. **GAP 1 (BLOCKER, ref: uat/1)** — The Grants.gov search client POSTs to the wrong
   path (`${GRANTS_GOV_BASE}/search2/opportunities/search`), which returns **HTTP 403
   Forbidden** on every page. The correct endpoint is `${GRANTS_GOV_BASE}/search2`
   (POST, same JSON body, same `data.oppHits` response envelope). Because the code
   `throw`s on `!res.ok`, every downstream Phase 8 UAT flow (browse/save/alerts/import/
   versions/sync) is blocked — no external opportunity data can exist. The existing
   integration mocks are ALSO pinned to the wrong path (`.includes('/search2/opportunities/search')`),
   which is exactly why the test suite stayed green while live UAT hit 403: the mocks
   validated the broken path. Fixing the endpoint requires re-pinning the mocks to the
   correct `/search2` path so the regression is caught by the suite going forward.

2. **GAP 2 (gate, ref: gate/boot_smoke)** — GATE.md frontmatter has no `boot_smoke` key.
   The app DOES boot (UAT self-check: frontend :5173 up, backend :3000 healthy, db+redis
   healthy) — the verdict was simply never recorded. Record it.

3. **GAP 3 (gate, ref: gate/review_blockers_open)** — GATE.md frontmatter has no
   `review_blockers_open` key; an absent count reads unsafely as zero. Record the count.

Purpose: Make Grants.gov ingestion actually work end-to-end so the Phase 8 goal
(ingest → normalize → persist → save/track/compare/import → alert) is achievable, and
close the two recording gaps so execute-phase has a verdict on every gate path.

Output: Corrected search endpoint + regression-pinning tests proving ingestion returns
>0; boot_smoke and review_blockers_open verdicts written to GATE.md.
</objective>
