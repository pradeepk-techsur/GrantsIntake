# Plan 08-04: Scheduled Refresh & Change Alerts

**Plan:** 08-04 of 05

---

## Goal

Ensure the system automatically refreshes imported Grants.gov opportunities on a schedule and delivers in-app alerts to users when tracked opportunities change (due date, status, package, addenda, instructions).

---

## Tasks

### Task 1: Env Configuration

Add to `.env.example`:
```
GRANTS_GOV_REFRESH_CRON="0 */6 * * *"
GRANTS_GOV_API_BASE_URL="https://api.grants.gov/v1/api"
GRANTS_GOV_MAX_PAGES=5
GRANTS_GOV_PAGE_SIZE=25
```

---

### Task 2: Scheduler Startup Integration

**File:** `src/index.ts` (extend)

After `app.listen(...)`:
```ts
import { startIngestionScheduler } from './services/ingestionScheduler';
startIngestionScheduler();
```

`startIngestionScheduler()` reads `GRANTS_GOV_REFRESH_CRON` from env (default `0 */6 * * *`) and schedules `refreshAll()`. Logs cron expression on startup.

---

### Task 3: Change Detection Logic

**File:** `src/services/externalOpportunityService.ts` (extend)

`detectChanges(existing: NormalizedOpportunity, incoming: NormalizedOpportunity): ChangedField[]`

Watched fields (PRD-INTAKE-019D):
- `due_date` → alert_type: `due_date_change`
- `opportunity_status` → alert_type: `status_change`
- `application_package_url` → alert_type: `package_change`

If `raw_metadata.synopsis.synopsisAddendum` changed → `addenda_change`  
If `raw_metadata.packages[].instructions` changed → `instructions_change`

Returns array of `{ field, previousValue, newValue, alertType }`.

### Task 4: Alert Delivery Test

**File:** `src/tests/ingestionScheduler.test.ts`

Using `nock` to simulate Grants.gov API returning an updated `due_date`:
1. Seed existing `external_opportunity` with `due_date = '2026-11-01'` and one `saved_external_opportunity` row
2. Mock Grants.gov API to return same opportunity with `due_date = '2026-12-01'`
3. Call `refreshAll()`
4. Assert: `change_alerts` row created for the saving user with `alert_type = 'due_date_change'`, `previous_value = '2026-11-01'`, `new_value = '2026-12-01'`
5. Assert: `external_opportunity_versions` row created with `changed_fields = ["due_date"]`

## Acceptance Criteria

1. Scheduler starts on server boot using `GRANTS_GOV_REFRESH_CRON` env var
2. `refreshAll()` runs without error when Grants.gov API is reachable
3. When a re-fetch returns an updated `due_date`, a `change_alerts` row is created for all users who saved that opportunity
4. `external_opportunity_versions` row captures the `changed_fields` diff
5. Grantor admin can trigger a manual sync from the dashboard
6. Integration test covering the change detection → alert creation pipeline passes
