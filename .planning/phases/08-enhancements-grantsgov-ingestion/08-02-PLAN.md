# Plan 08-02: Grants.gov Opportunity Browser — Frontend UI

**Phase:** 8 — Enhancements: Grants.gov Opportunity Ingestion  
**Plan:** 08-02 of 05  
**Status:** Pending  
**Requirements:** PRD-INTAKE-019C  
**Depends on:** 08-01 (backend service and API must exist)  
**Created:** 2026-09-02

---

## Goal

Add a "Browse Grants.gov" page to the applicant portal that lets applicants search, filter, save, and track external funding opportunities pulled live from Grants.gov, using the GrantFlow Design System v1.0.

---

## Tasks

### Task 1: API Client

**File:** `client/src/api/externalOpportunitiesApi.ts`

Functions (all call `/api/v1/external-opportunities`):
- `listExternalOpportunities(params)` — GET with query params
- `getExternalOpportunity(id)` — GET /:id
- `getVersionHistory(id)` — GET /:id/versions
- `saveOpportunity(id)` — POST /:id/save
- `unsaveOpportunity(id)` — DELETE /:id/save
- `listSaved()` — GET /saved
- `listAlerts()` — GET /alerts
- `markAlertRead(alertId)` — PUT /alerts/:alertId/read

---

### Task 2: ExternalOpportunityBrowserPage

**File:** `client/src/pages/applicant/ExternalOpportunityBrowserPage.tsx`  
**Route:** `/applicant/grants-gov`

Layout: two-column — filter sidebar (left) + results (right), matching GrantFlow DS pattern.

Filter sidebar (`gf-filter-panel`):
- Status: posted | forecasted | closed | archived (checkbox group)
- Agency: text search input
- Keyword: text input
- Due date range: from/to date inputs
- Award ceiling: min/max number inputs
- Clear filters button

Results panel:
- Page title: "Browse Grants.gov Opportunities"
- Source attribution badge: "Powered by Grants.gov API" (`gf-badge gf-badge--info`)
- Pagination controls (25 per page)
- Each result: `ExternalOpportunityCard` component (see Task 3)
- Empty state: "No opportunities found. Try adjusting your filters."
- Loading skeleton while fetching

---

### Task 3: ExternalOpportunityCard Component

**File:** `client/src/components/ExternalOpportunityCard.tsx`

Displays per opportunity:
- Title (linked to detail page)
- Agency name + `gf-badge` for status (posted=success, forecasted=info, closed=neutral, archived=muted)
- Opportunity Number + Assistance Listing (if present)
- Due date (highlighted in warning color if within 14 days)
- Award ceiling / floor range
- Eligibility summary (truncated to 2 lines)
- Save/Unsave button: heart icon toggle (`gf-btn gf-btn--ghost`) — calls save/unsave mutation
- "View Details" link

---

### Task 4: ExternalOpportunityDetailPage

**File:** `client/src/pages/applicant/ExternalOpportunityDetailPage.tsx`  
**Route:** `/applicant/grants-gov/:id`

Sections:
- Header: title, agency, status badge, FON, import timestamp ("Last updated from Grants.gov: {date}")
- Metadata grid: due date, award ceiling/floor, assistance listing, package URL (external link), source URL (Grants.gov link)
- Eligibility summary panel (`gf-alert gf-alert--info`)
- Source attribution footer: "Source: Grants.gov API · Imported {import_timestamp} · Reference: {source_opportunity_number}"
- Version history accordion: each version shows changed fields, snapshot date
- Action bar: Save/Unsave button + "Import to Workspace" button (PRD-INTAKE-019C) — navigates to opportunity creation flow pre-filled with external metadata

## Acceptance Criteria

1. Applicant can navigate to "Browse Grants.gov" from the sidebar
2. Filter controls update the result list in real time (on filter change or Apply click)
3. Save button on a card persists the save and shows the opportunity in "Saved from Grants.gov" on dashboard
4. Detail page shows full normalized metadata, source attribution, and version history
5. Alert bell shows unread count and mark-as-read works inline
6. All E2E tests pass
