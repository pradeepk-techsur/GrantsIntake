CREATE TABLE intake_dispositions (
    disposition_id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    snapshot_id                 UUID NOT NULL REFERENCES submission_snapshots(snapshot_id),

);
CREATE INDEX idx_dispositions_entry ON intake_dispositions(entry_id);

-- Add FK from intake_queue_entries to intake_dispositions (after both created)

    request_id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),

CREATE INDEX idx_review_handoffs_entry ON review_handoffs(entry_id);

CREATE TABLE notification_records (

CREATE INDEX idx_notifications_recipient ON notification_records(recipient_user_id, is_read);

**Step 2 — Create `src/services/intake/intakeQueueService.ts`**

Class `IntakeQueueService` with methods:

- `getQueueEntries(filters: {opportunity_id?, status?, sort_by?, page?, page_size?}, grantorOrgId: string)`: Query intake_queue_entries JOIN submission_snapshots JOIN organizations JOIN opportunities WHERE opportunity.grantor_org_id = grantorOrgId (IDOR guard — grantor can only see queue entries for their own org's opportunities). Return array with: entry_id, workspace_id, opportunity_id, opportunity_title, org_id, org_name (from organizations.legal_name), snapshot_id, status, routed_to, created_at, submission_timestamp (snapshot.submitted_at), confirmation_number, requested_amount (from snapshot.budget_snapshot->>'total_federal_requested' cast to numeric), attachment_count (JSONB array length of snapshot.attachment_refs), eligibility_result (from snapshot.eligibility_snapshot->>'overall_result'), validation_summary (snapshot.validation_summary), disposition_id. Support sort_by: submission_date (snapshot.submitted_at), org_name (organizations.legal_name), funding_amount (budget total), eligibility_result. Default sort: submission_date DESC. Paginate with LIMIT/OFFSET from page/page_size (default page=1, page_size=25). Return {entries, total, page, page_size}.

- `getEntryDetail(entryId: string, grantorOrgId: string)`: Fetch single entry with full snapshot data (all snapshot JSONB fields). JOIN opportunity to verify grantor_org_id = grantorOrgId (IDOR guard — throw 403 if mismatch). Also fetch active correction_requests for this entry, disposition history (all intake_dispositions rows for this entry_id ORDER BY applied_at DESC).

- `applyDisposition(entryId: string, payload: {disposition: string, rationale?: string, screening_criteria_results?: object[]}, appliedBy: string, grantorOrgId: string)`: Validate disposition is one of: accepted_for_review, returned_for_correction, ineligible, late, duplicate, withdrawn, administratively_rejected. Validate rationale is required for all non-acceptance dispositions (return 422 with RATIONALE_REQUIRED if missing). Verify entry belongs to grantorOrgId (IDOR guard). INSERT into intake_dispositions, then UPDATE intake_queue_entries SET status=disposition, disposition_id=new_disposition_id, updated_at=now(). Create DISPOSITION_APPLIED audit event. Notify applicant team (all users in org_roles for the workspace's org_id with title 'Disposition Applied' and body describing the decision). Return created disposition row.

- `createNotification(recipientUserId: string, notificationType: string, entityType: string, entityId: string, title: string, body: string, actionUrl?: string)`: INSERT into notification_records. Used by applyDisposition and correction flow.

- `getNotifications(userId: string, filters: {is_read?: boolean, page?: number, page_size?: number})`: SELECT from notification_records WHERE recipient_user_id=$1, optional is_read filter, ORDER BY created_at DESC, paginated.

- `markNotificationRead(notificationId: string, userId: string)`: UPDATE notification_records SET is_read=true WHERE notification_id=$1 AND recipient_user_id=$2 (ownership check). Return 404 if not found.

Export `export const intakeQueueService = new IntakeQueueService();`

```
GET /intake-queue — requireRole('grantor_admin','program_officer','intake_administrator','compliance_analyst','reviewer'); extract grantorOrgId from user's grantor_memberships (join users→grantor_memberships); call intakeQueueService.getQueueEntries(query, grantorOrgId); return 200 {entries, total, page, page_size}

GET /intake-queue/:entryId/snapshots — requireRole('grantor_admin','program_officer','intake_administrator','compliance_analyst','reviewer'); query submission_snapshots WHERE workspace_id = (SELECT workspace_id FROM intake_queue_entries WHERE entry_id=$1) ORDER BY submitted_at ASC; return array with snapshot_id, confirmation_number, submitted_at, is_original, is_current; verify entry belongs to grantorOrgId

GET /notifications — authenticate only (no role restriction — applicants and grantors both receive notifications); intakeQueueService.getNotifications(req.user.user_id, query); return {notifications, total, page, page_size}

PUT /notifications/:notificationId/read — authenticate only; intakeQueueService.markNotificationRead(notificationId, req.user.user_id); return 200 {updated: true}
```

For grantorOrgId extraction: query `SELECT go.org_id FROM grantor_organizations go JOIN grantor_memberships gm ON gm.org_id=go.org_id WHERE gm.user_id=$1 LIMIT 1`. Use pool directly in router helper.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Elevation of privilege / Information disclosure | GET /intake-queue — IDOR: grantor A reading entries belonging to grantor B's opportunities | mitigate | `intakeQueueService.getQueueEntries()` JOINs `opportunities` and filters `WHERE opportunities.grantor_org_id = grantorOrgId`; `getEntryDetail()` verifies the same condition and throws 403 if mismatch; grantorOrgId is server-derived from `grantor_memberships` (never client-supplied) |
| T-06-02 | Elevation of privilege | POST /intake-queue/:entryId/disposition — applicant or non-grantor applying disposition | mitigate | `requireRole('grantor_admin','intake_administrator')` applied at router layer before handler runs; returns 403 PERMISSION_DENIED for all other roles |
| T-06-03 | Tampering | POST /intake-queue/:entryId/disposition — invalid disposition value injected (e.g., SQL fragment) | mitigate | Zod enum validation in route handler restricts disposition to exactly 7 allowed values; parameterized `pool.query()` for all DB writes — no string interpolation |
| T-06-04 | Information disclosure | GET /intake-queue/:entryId/snapshots returning snapshots for entries the grantor doesn't own | mitigate | Route handler resolves workspace_id from entry_id and verifies opportunity.grantor_org_id = grantorOrgId before returning snapshot list |

| T-06-06 | Repudiation | Disposition applied without attribution | mitigate | Every `intake_dispositions` INSERT records `applied_by = req.user.user_id` and `applied_at = now()`; DISPOSITION_APPLIED audit event written with actor_user_id — disposition history is append-only (no UPDATE/DELETE on intake_dispositions) |
