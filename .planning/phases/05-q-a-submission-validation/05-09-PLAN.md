  <name>Task 1: Reseed UAT opportunities under admin@example.gov's grantor org and program</name>
  <files>src/db/seed.ts</files>
  <action>
The problem: UAT-OPP-001 and UAT-OPP-002 are seeded under a separate 'UAT Federal Agency' grantor org and 'UAT Grant Program' program. admin@example.gov only has grantor_admin membership in 'Example Federal Agency'. OpportunitiesIndex fetches `/programs` (scoped to the admin's org), finds only 'General Grant Programs', and then fetches opportunities under that program — which contains no UAT opportunities.

The fix: Remove the 'UAT Federal Agency' / 'UAT Grant Program' seeding entirely. Instead seed UAT-OPP-001 and UAT-OPP-002 directly under 'General Grant Programs' (the program already seeded for 'Example Federal Agency' / admin@example.gov). The workspace, org, org_roles, and form_field_definitions seeding can remain exactly as-is — only the grantor org/program/opportunity linkage changes.

Surgical changes to src/db/seed.ts:

1. **Remove** the "1. Grantor org for the UAT opportunity" block (the `existingUatGrantorOrg` / `uatGrantorOrgId` select-then-insert). Delete it entirely.

2. **Remove** the "2. Grant program for the UAT opportunity" block (the `existingUatProgram` / `uatProgramId` select-then-insert). Delete it entirely.

3. **Change** the "3. Published opportunity" block so it uses `programId` (the General Grant Programs program from admin's org, already in scope from step above) instead of `uatProgramId`. After the `programId` is determined (the `existingProgram` / program seed block), capture that value. Then in the UAT opportunity INSERT, replace `uatProgramId` with the `programId` variable (the General Grant Programs program_id).

   Concretely: after the `console.log('Seeded default program...')` line, capture the program_id:

   ```typescript
   // Capture the General Grant Programs program_id for UAT opportunities
   const mainProgramResult = await pool.query(
     `SELECT program_id FROM programs WHERE grantor_org_id = $1 AND program_name = $2 LIMIT 1`,
     [orgId, 'General Grant Programs'],
   );
   const mainProgramId = mainProgramResult.rows[0]?.program_id;
   ```

   Then in the UAT opportunity INSERT for UAT-OPP-001 and UAT-OPP-002, replace `uatProgramId` with `mainProgramId`.

4. **Remove all references** to `uatGrantorOrgId` and `uatProgramId` variables (they will no longer be declared).

5. **Update the console.log** at the end from `'Seeded UAT scenario: UAT-OPP-001 + UAT Test Nonprofit + workspace (idempotent)'` to mention opportunities are now under General Grant Programs.

IMPORTANT — idempotency: The existing seed may already have UAT-OPP-001 rows under the old UAT program. The seed's idempotency guard uses `opportunity_number = 'UAT-OPP-001'` (SELECT-then-INSERT) which will find the existing row and skip re-insert regardless of which program_id it has. To ensure the opportunity is under the correct program after re-seed, change the existing opportunity check to also UPDATE the program_id if found:

```typescript
// For UAT-OPP-001:
const existingUatOpportunity = await pool.query(
  `SELECT opportunity_id FROM opportunities WHERE opportunity_number = $1`,
  ['UAT-OPP-001'],

let uatOpportunityId: string;
if (existingUatOpportunity.rows.length > 0) {
  uatOpportunityId = existingUatOpportunity.rows[0].opportunity_id;
  // Re-assign to correct program (idempotent migration of existing row)
  await pool.query(
    `UPDATE opportunities SET program_id = $1 WHERE opportunity_id = $2`,
    [mainProgramId, uatOpportunityId],
  );
} else {
  // INSERT as before but with mainProgramId
  ...
}
```

Apply the same UPDATE pattern to UAT-OPP-002.

This ensures existing environments get the opportunity re-parented to the correct program on next seed run.

<task type="auto">
  <name>Task 2: Fix OpportunitiesIndex to fetch all programs for the grantor's org (not just the first)</name>
  <files>client/src/pages/grantor/OpportunitiesIndex.tsx</files>
  <action>
The current `useFirstProgramId()` hook fetches only the FIRST program and uses that single program's opportunities. If the admin has multiple programs, opportunities in other programs are invisible. The correct approach: fetch ALL programs for the admin's org and combine their opportunities into one list.

Replace the single-program approach with a multi-program approach:

1. **Replace `useFirstProgramId`** with a `useAllOpportunities` hook (or inline effect) that:
   - Fetches `GET /api/v1/programs` to get all programs for the logged-in grantor's org
   - For each program, fetches `GET /api/v1/programs/:programId/opportunities`
   - Flattens all results into a single `opportunities` array

2. **Keep the TemplateLibrary modal working**: the `programId` prop for the modal should use the first program (just for creating new opportunities). Keep `programId` as a local variable for that purpose — it's fine to use the first program for the create path.

3. **Update the `useEffect`** for opportunity loading to iterate all programs:

```typescript
useEffect(() => {
  setLoading(true);
  apiClient
    .get<{ program_id: string }[]>('/programs')
    .then(async (res) => {
      const programs = res.data;
      if (programs.length === 0) {
        setOpportunities([]);
        return;
      }
      // Set programId for create modal (first program)
      if (programs[0]) setProgramId(programs[0].program_id);
      // Fetch all opportunities across all programs
      const oppArrays = await Promise.all(
        programs.map((p) =>
          apiClient
            .get<OpportunityListItem[]>(`/programs/${p.program_id}/opportunities`)
            .then((r) => r.data)
            .catch(() => [] as OpportunityListItem[]),
        ),
      );
      setOpportunities(oppArrays.flat());
    })
    .catch(() => setOpportunities([]))
    .finally(() => setLoading(false));
}, []);
```

4. **Convert `programId` state to `useState<string | null>(null)`** (already is) — it's now set inside the effect instead of in `useFirstProgramId`. Remove the `useFirstProgramId` hook entirely from the file.

5. **Keep all existing JSX unchanged** — the opportunities list rendering, the "Manage Q&A" links, the TemplateLibrary modal, and the "no programs" warning all remain as-is.

Note: This also means the 'UAT Community Health Innovation Grant' and 'UAT Community Health Grant 2' will appear in the Opportunities list for admin@example.gov after the seed fix in Task 1, because they now live under 'General Grant Programs' which belongs to admin's org.
