## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server→localStorage | org_id UUID written to localStorage from authenticated API response — non-sensitive identifier (no auth tokens stored) |
| seed→database | Seed inserts are developer-controlled, run only in development/test containers — no untrusted input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Information disclosure | localStorage.applicant_org_id | accept | org_id is a non-sensitive UUID; accessing org data requires a valid auth token (Phase 3 decision, T-03-10 accepted risk already recorded in STATE.md). Owner: this plan (mirrors existing accepted risk). |
| T-05-05-02 | Tampering | useIsAuthorizedRep localStorage read | mitigate | org_id from localStorage is only used as a query parameter to GET /organizations/:org_id/roles — the server enforces auth via verifyAccessToken middleware before returning roles; a tampered org_id returns a different org's roles but cannot escalate privileges since the response is filtered by the authenticated user's user_id in the hook (`roles.find(r => r.user_id === user.user_id)`). |
| T-05-05-03 | Elevation of privilege | Seed form_field_definitions | accept | Seed runs only in development containers behind docker compose — no production exposure. Owner: infrastructure/DevOps. |
</threat_model>
