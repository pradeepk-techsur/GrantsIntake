<objective>
Fix the "Create Opportunity button does nothing" gap identified in UAT Test 3.

Root cause: `seed.ts` inserts no rows into the `programs` table → `GET /api/v1/programs` returns `[]` → `useFirstProgramId()` returns `null` → `TemplateLibrary` modal is gated on `programId` being truthy and never mounts. The button click sets `showTemplateLibrary=true` but the modal is silently suppressed with an unlabeled, unhelpful warning alert.

Fix 1 (required): Add an idempotent program seed to `src/db/seed.ts` so a program row exists after every boot. This makes `programId` non-null and the template modal reachable.

Fix 2 (defensive UX): Upgrade the `!programId` warning alert in `OpportunitiesIndex.tsx` to include a `usa-alert__heading` and actionable text — so edge-case dev environments (fresh clone, skipped seed) produce a legible error state rather than a silent no-op.

Purpose: Unblock UAT Tests 3–7. Tests 4–7 are all skipped because the Opportunity Builder is unreachable via the UI.
Output: A working "Create Opportunity" flow: template selection → modal → Opportunity Builder navigation.
</objective>

The `programs` table DDL (from `src/db/migrations/002_opportunity_schema.sql`):
```sql
CREATE TABLE programs (
    program_id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    grantor_org_id      UUID NOT NULL REFERENCES grantor_organizations(org_id),
    program_name        VARCHAR(250) NOT NULL,
    program_area        VARCHAR(100),
    is_federal          BOOLEAN NOT NULL DEFAULT FALSE,
    program_description TEXT,
    created_by          UUID NOT NULL REFERENCES users(user_id),
    created_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now(),
    archived_at         TIMESTAMPTZ
);
```

Insert this block immediately after `console.log('Grantor role assigned...')`:

```typescript
// Seed default program (idempotent — check before insert, no UNIQUE constraint on name)
const existingProgram = await pool.query(
  `SELECT 1 FROM programs WHERE grantor_org_id = $1 AND program_name = $2`,
  [orgId, 'General Grant Programs'],
);
if (existingProgram.rows.length === 0) {
  await pool.query(
    `INSERT INTO programs
       (grantor_org_id, program_name, program_area, is_federal, program_description, created_by)
     VALUES ($1, $2, $3, TRUE, $4, $5)`,
    [
      orgId,
      'General Grant Programs',
      'General',
      'Default program for Example Federal Agency. Used for creating and managing funding opportunities.',
      adminUserId,
    ],
  );
}
console.log('Seeded default program: General Grant Programs (idempotent)');
```

**Why SELECT-then-INSERT instead of ON CONFLICT DO NOTHING:** The `programs` table has no UNIQUE constraint on `program_name` — only a PRIMARY KEY on `program_id`. `ON CONFLICT DO NOTHING` would silently fail without a unique constraint to match on. The SELECT-then-INSERT pattern mirrors how the `grantor_organizations` block works in lines 28–44 of the same file.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| db→seed | Seed script runs with full DB credentials; inserts data that becomes trusted application state used by the auth and programs API |
| client→API | `useFirstProgramId` fetches `/api/v1/programs` with an authenticated token; the response drives UI state (modal gate) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-GAP-01 | Tampering | `src/db/seed.ts` program INSERT | accept | All values are hardcoded string literals — no user-controlled input flows into the INSERT. Residual risk: compromised container could alter `seed.ts` before boot. Owned by deployment environment security, not application code. |
| T-01-GAP-02 | Information disclosure | `OpportunitiesIndex.tsx` warning alert | mitigate | Warning text discloses the internal model name "program" but no credentials, user IDs, or enumerable data. Guard: the `canCreate` role-check at line 33 (requires `grantor_admin` or `program_officer`) ensures this component and its warning are never rendered to unauthenticated or non-grantor users. Mitigation in `client/src/pages/grantor/OpportunitiesIndex.tsx` `canCreate` gate. |
| T-01-GAP-03 | Elevation of privilege | `GET /api/v1/programs` (consumed by `useFirstProgramId`) | mitigate | Route requires `authenticate` middleware and derives `grantor_org_id` from `getGrantorOrgIdForUser(userId)` — never from the request body (T-02-01 IDOR mitigation already established in `src/services/program/programService.ts`). No new attack surface introduced by this plan. |
