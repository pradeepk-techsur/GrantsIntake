Create `src/db/migrations/004_opportunity_versions_schema.sql` with the EXACT DDL from TechArch (copy verbatim):

```sql
CREATE TABLE opportunity_versions (
    version_id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    opportunity_id          UUID NOT NULL REFERENCES opportunities(opportunity_id),
    version_number          INTEGER NOT NULL,
    snapshot                JSONB NOT NULL,
    delta                   JSONB,
    modification_reason     TEXT NOT NULL,
    created_by              UUID NOT NULL REFERENCES users(user_id),
    created_at              TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_opportunity_version UNIQUE (opportunity_id, version_number)
);
CREATE INDEX idx_opp_versions_opportunity ON opportunity_versions(opportunity_id);

-- IMMUTABLE: trigger rejects UPDATE/DELETE
CREATE OR REPLACE FUNCTION prevent_version_mutation()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  RAISE EXCEPTION 'opportunity_versions rows are immutable';
END;
$$;
CREATE TRIGGER opportunity_versions_immutable
  BEFORE UPDATE OR DELETE ON opportunity_versions
  FOR EACH ROW EXECUTE FUNCTION prevent_version_mutation();
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | POST /opportunities/:id/publish — publishing another org's opportunity | mitigate | `completenessService.check()` and publish handler both call `opportunityService.getById()` which verifies `program.grantor_org_id = req.user.grantor_org_id`; 403 on mismatch (IDOR protection, same pattern as 01-03) |
| T-04-02 | Repudiation | No record that modification_reason was supplied for a post-publication change | mitigate | `versioningService.createSnapshot()` stores modification_reason in `opportunity_versions.modification_reason` (NOT NULL) and in `audit_events.payload.modification_reason`; immutable trigger on both tables prevents after-the-fact changes |
| T-04-03 | Tampering | JSONB snapshot in opportunity_versions manipulated post-insert | mitigate | DB trigger `opportunity_versions_immutable` (in 004 migration) rejects UPDATE/DELETE on opportunity_versions rows; application layer cannot bypass; integration test asserts trigger fires |
| T-04-04 | Elevation of Privilege | Non-program-officer role calls POST /publish to force publication | mitigate | `requireRole('grantor_admin','program_officer')` middleware in `src/routes/opportunities.ts` blocks intake_administrator, compliance_analyst, reviewer roles with 403 |
| T-04-05 | Denial of Service | Rapid repeated POST /publish calls to spam audit_events | mitigate | express-rate-limit (100 req/min per authenticated user from plan 01-01) applies to all /api/v1 routes; publish endpoint additionally checks current status to prevent re-publishing already-published opportunity (returns 409) |
| T-04-06 | Information Disclosure | Version snapshot JSONB exposes internal fields to unauthorized callers | mitigate | GET /opportunities/:id/versions guarded by authenticate middleware; `versioningService.listVersions()` verifies opportunity's org matches `req.user.grantor_org_id` before returning versions |
| T-04-07 | Tampering | dry_run query param abused to probe completeness without proper auth | mitigate | POST /opportunities/:id/publish (including dry_run=true variant) still requires authenticate + requireRole('grantor_admin','program_officer'); no public completeness probe endpoint |
</threat_model>
