**Fix 2: Use visible USWDS file input instead of display:none (lines 136-144)**

Replace the hidden `<input>` with a visible USWDS file input label pattern. The USWDS usa-file-input renders a styled file picker. Since we're using a ref-triggered click pattern for the upload button, keep the input functional but use USWDS classes and `aria-hidden` + `tabIndex={-1}` so it's visually handled by the button while still usable:

```tsx
{/* USWDS file input — visually hidden via positioning, accessible via Upload button trigger */}
<input
  ref={fileInputRef}
  type="file"
  className="usa-file-input"
  style={{ position: 'absolute', width: '1px', height: '1px', overflow: 'hidden', clip: 'rect(0,0,0,0)', whiteSpace: 'nowrap' }}
  onChange={handleFileUpload}
  aria-label="Upload attachment file"
  tabIndex={-1}
/>
```

Using CSS clip/positioning instead of `display:none` allows the USWDS class to apply its styles while keeping the element out of the tab order (the "Upload New File" button is the actual interactive trigger). This satisfies USWDS styling requirements while preserving the ref-click pattern.

**Fix 3: Change usa-table--striped to usa-table--borderless (line 150)**

```tsx
{/* Before */}

{/* After */}
```

**Fix 4: Use usa-button--secondary for Delete button instead of inline color (line 190-195)**

In the action cell, the Delete button currently uses:
```tsx
<button
  type="button"
  className="usa-button usa-button--unstyled"
  onClick={() => setConfirmDelete(att.attachment_id)}
  style={{ color: '#b50909', fontSize: '0.875rem' }}
>
  Delete
</button>
```

Change to use `usa-button--unstyled` with a `usa-tag` to indicate destructive action, OR simply use `usa-button--secondary usa-button--unstyled` to get semantic color without explicit inline style:

```tsx
<button
  type="button"
  className="usa-button usa-button--unstyled"
  onClick={() => setConfirmDelete(att.attachment_id)}
  style={{ fontSize: '0.875rem' }}
  data-testid={`delete-attachment-btn-${att.attachment_id}`}
>
  <span style={{ color: 'var(--usa-color-secondary-dark, #b50909)' }}>Delete</span>
</button>
```

Actually, for full USWDS conformance, replace the inline color with the USWDS CSS variable for the secondary/danger color (`--usa-color-secondary-dark` or `--usa-color-red-warm-70v`). If USWDS CSS variables are not available in this project's config, use the existing approach but without the inline hex — check what color token is used elsewhere in the codebase (BudgetBuilder uses `style={{ color: '#b50909' }}` on Remove too; for now align with that but note the semantic class approach):

The cleanest USWDS-conformant fix is:
```tsx
<button
  type="button"
  className="usa-button usa-button--unstyled usa-button--secondary"
  onClick={() => setConfirmDelete(att.attachment_id)}
  style={{ fontSize: '0.875rem' }}
  data-testid={`delete-attachment-btn-${att.attachment_id}`}
>
  Delete
</button>
```

Remove the `style={{ color: '#b50909' }}` inline color entirely — `usa-button--secondary` applies the USWDS red semantically.
